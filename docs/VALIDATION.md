## 0.1.1 预览自适应修复

2026-10-18：用户提供的分式在固定 48px 字号下被预览框裁切。已改为测量 KaTeX 的原始排版宽高，按可用区域等比缩小；编辑公式、窗口尺寸或字体加载变化都会重新测量，短公式恢复正常大小。设置里的小预览使用同一组件。

`npm run verify` 通过，Svelte 0 errors / 0 warnings；Windows release EXE 与 NSIS 0.1.1 构建成功。浏览器实际渲染验证了用户分式的浅/暗色、620px 窄窗、5 行矩阵、长求和积分公式、长公式改短以及窄窗拉宽。7 个 DOM 边界样本全部包含在预览区域内，见 `test-results/preview-fit/measurements.json`；截图与同图比较位于同目录。这里只验证显示适配，不重复宣称已重跑原生 50 次循环或 Mac 实机。

新版位于 `output/My-Snip-0.1.1.exe` 与 `output/My-Snip-0.1.1-x64-setup.exe`；当前运行的旧版没有被终止，避免丢失当前编辑的公式。

以下为 0.1.0 原生闭环和内存验证的历史记录。

2026-10-18，Windows 11 专业版 10.0.28000，16 逻辑处理器、61.7 GiB RAM。Rust 1.98.1、Node 24.20.0；依赖精确版本见锁文件。实际桌面为 1920×1080，测试选区由应用的原生框选处理函数提交；没有模拟全局按键或鼠标拖动。

## 内存实测

采样脚本 `scripts/measure-memory.ps1` 根据本应用 PID 追踪 WebView2 后代进程，每约 1 秒采样。工作集相加可能重复计算共享页面；private 数字是私有提交内存，不等同于物理驻留。关闭 DevTools，采用打包前端，未把 Vite / Rust 编译器或其他应用的 WebView 计入。

| 状态 | 工作集合计 MiB | 私有提交 MiB | WebView2 子进程 |
| --- | ---: | ---: | ---: |
| 首轮结果窗显示样本 | 387.50 | 203.61 | 6 |
| 首轮采样峰值 | 458.62 | 203.61 | 随状态变化 |
| 最终 50 次循环后约 30 秒 | 38.17 | 9.11 | 0 |
| 最终 50 次循环后约 120 秒 | 38.11 | 9.02 | 0 |

首轮完整采样在 `test-results/native-release/memory-samples.csv` / `memory-summary.json`；最终循环和 30/120 秒样本在 `test-results/native-final/` 同名文件。最终采样启动晚于结果窗，因此结果显示与首轮峰值取自首轮，不混称同一轮观测。最终轮观测到的峰值为 379.06 MiB，但它没有覆盖全部阶段，不能替代首轮峰值。

测试构建包含诊断与剪贴板备份辅助代码，发布构建去除了该 feature。当前证据表明收起后无 WebView 残留且工作集回落，不把一次 50 次测试视为长期无泄漏保证；未对 4K、混合 DPI 或 Mac 内存作实测结论。

## 交付与构建

安装包与免安装程序位于 `output/`，SHA-256 和字节数记在 `output/artifacts.json`。安装包使用当前用户安装模式，包含第三方许可；不携带 API Key，不需要 Node/Rust 运行时。免安装 EXE 依赖系统 WebView2 Runtime；安装器会检测运行时。

打包期间全局 NSIS 缓存的重分析路径报错，已改为项目内 `target/.tauri/` 缓存并通过官方包校验下载。独立二次打包曾提示缺少 updater bundle 标记；本版没有自动更新插件，最终完整构建重新生成二进制并打包。

macOS 的截图权限、CoreGraphics 鼠标坐标、来源应用恢复、Keychain、LSUIElement、Intel/Apple Silicon 构建配置已经实现。CI 已写入但未推送或执行，当前环境无法产出经过验证的 Mac 安装包。CI 的 ad-hoc 签名不等同于 Apple 公证。
